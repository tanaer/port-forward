# goForward v1.7.x vs v2.0.0 使用指南

## 版本差异说明

### v1.7.x - 单机版 (当前运行的版本)
- **架构**: 单机版，直接运行代理服务
- **文件**: `main.go` (v1.7.x)
- **用途**: 本地端口转发，单节点运行
- **特性**:
  - TCP/UDP端口转发
  - Web界面 (端口8889)
  - 本地数据库 (goForward.db)
  - 支持多种代理协议 (Hysteria2, Xray等)

### v2.0.0 - 分布式版 (新开发的功能)
- **架构**: 控制端-代理端分布式架构
- **文件**: `main_v2.go` (示例启动)
- **用途**: 多节点分布式管理
- **特性**:
  - 控制端管理多个代理端
  - gRPC通信
  - 配置版本管理
  - 配置回滚
  - Prometheus指标
  - 死信队列(DLQ)
  - 节点健康检查

## 如何启动v2.0.0

### 方法1: 直接启动v2.0.0主程序 (需要修改)
```bash
# 目前v2.0.0还没有单独的启动入口，需要完成集成
# TODO: 完成control/web和control/server的启动集成
```

### 方法2: 编译v2.0.0控制端
```bash
# 1. 进入控制端目录
cd control

# 2. 启动控制服务器 (gRPC)
go run ./server/*.go

# 3. 启动Web界面 (新窗口)
go run ./web/*.go

# 4. 启动Prometheus指标 (新窗口)
go run ./metrics/*.go
```

### 方法3: 分离启动模式
```bash
# 启动控制端 (管理界面)
cd control/server && go run .

# 启动代理端 (需要部署到各节点)
cd agent/client && go run .
```

## 当前状态说明

您的服务器目前运行的是**v1.7.1.1单机版**，这是正常现象。

v2.0.0的分布式功能虽然代码已经完成，但还没有完整的启动入口集成。这是两个独立的产品：

- **v1.7.x**: 生产可用，已发布
- **v2.0.0**: 开发完成，需要集成启动

## 如何使用分布式功能

如果您想体验v2.0.0的分布式功能，需要：

1. **完成v2.0.0启动入口的集成**
   - 将control/目录下的所有模块集成到main.go
   - 实现真正的分布式控制端启动

2. **部署代理端到各节点**
   - 将agent/目录下的代码部署到各代理服务器
   - 配置gRPC连接到控制端

3. **导入配置**
   - 将v1.7.x的配置迁移到v2.0.0
   - 在控制端Web界面管理节点

## 技术栈对比

| 功能 | v1.7.x | v2.0.0 |
|------|--------|--------|
| 架构 | 单机 | 分布式 |
| 通信 | HTTP | gRPC + HTTP |
| 数据库 | SQLite | SQLite (多层表) |
| 监控 | 无 | Prometheus |
| 管理 | 本地Web | 分布式Web |
| 配置 | 文件 | 版本化数据库 |
| 代理端 | 本进程 | 独立部署 |
